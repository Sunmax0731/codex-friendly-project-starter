## Security and package safety notes

ZIP import is for Codex Flow input files only. It is not a source-code patch package mechanism.

Allowed package contents:

```text
docs/**
prompts/**
.codexflow/flow.json
```

Forbidden package contents:

```text
src/**
package.json
package-lock.json
tests/**
dist/**
node_modules/**
.git/**
.env
.env.*
*.vsix
.codexflow/state.json
.codexflow/logs/**
.codexflow/run-prompts/**
.codexflow/backups/**
tmp/**
backup/**
*.bak
*.tmp
*.log
```

Runtime output restrictions:

```text
docs/handoff/**
.codexflow/logs/**
```

Handoff artifacts must remain under `docs/handoff/**`. Log artifacts must remain under `.codexflow/logs/**`.

Import does not automatically start Run All. Run Next, Run All, and Repair require explicit user action after package validation and import. Unsafe runtime output paths are validation errors, not warnings.

Use these commands to review the safe package authoring rules before preparing packages:

- `Codex Friendly: Open Safe ZIP Authoring Prompt`
- `Codex Friendly: Copy Safe ZIP Authoring Prompt`

## Installation guide

### VSIX install through VS Code

1. Download or receive `dist/codex-friendly-project-starter-0.1.0.vsix`.
2. Verify SHA256 equals `a5bf66c2e9146838f404f32900f59a714df39f00c4410ee48f7adf54280cf226`.
3. Open VS Code.
4. Run `Extensions: Install from VSIX...`.
5. Select `dist/codex-friendly-project-starter-0.1.0.vsix`.
6. Reload VS Code if prompted.
7. Confirm `Codex Starter:` and `Codex Friendly:` commands appear in the Command Palette.

### CLI install

```powershell
code --install-extension dist/codex-friendly-project-starter-0.1.0.vsix
```

### Isolated tester install

Create temporary user-data and extension directories, then launch VS Code with them:

```powershell
code --user-data-dir <temp-user-data-dir> --extensions-dir <temp-extensions-dir>
```

Install the VSIX inside that isolated session through `Extensions: Install from VSIX...`, or install with the same directories:

```powershell
code --user-data-dir <temp-user-data-dir> --extensions-dir <temp-extensions-dir> --install-extension dist/codex-friendly-project-starter-0.1.0.vsix
```

### Uninstall and reinstall

```powershell
code --uninstall-extension sunmax0731.codex-friendly-project-starter
code --install-extension dist/codex-friendly-project-starter-0.1.0.vsix
```

For isolated sessions, include the same `--user-data-dir` and `--extensions-dir` arguments used for install.

## Closed-alpha smoke checklist

Use `docs/releases/v0.1.0-rc.2-alpha-checklist.md` as the tester-facing checklist. At minimum, closed-alpha testers should verify:

- Install VSIX.
- Verify Command Palette commands.
- Open Safe ZIP Authoring Prompt.
- Copy Safe ZIP Authoring Prompt.
- Validate safe ZIP.
- Validate unsafe runtime ZIP.
- Validate disallowed source-code ZIP.
- Import safe ZIP.
- Confirm import does not auto Run All.
- Open Flow Dashboard.
- Open `flow.json`.
- Run one small Run Next phase.
- Open phase log.
- Optionally stop a running phase.
- Optionally run Run All.
- Optionally repair failed phase.
- Verify logs under `.codexflow/logs/**`.
- Verify handoff under `docs/handoff/**`.
- Verify no writes to `src/**` or `package.json`.
- Run one small real Codex CLI phase from the installed VSIX without a mock or stub.

## Known issues and limitations

- Low: Some Manual UI / installed VSIX evidence is operator-reported or harness-captured, not full screenshot/log capture for every UI picker and dialog.
- Low hardening note: A BOM-prefixed pre-existing `.codexflow/state.json` can cause JSON parse failure when opening the dashboard. Extension-authored state files are UTF-8 without BOM. Workaround: rewrite `.codexflow/state.json` as UTF-8 without BOM or regenerate state. Recommended follow-up: tolerate UTF-8 BOM or show a clearer recovery message.
- Alpha validation note: Installed VSIX smoke used a stub/mock for deterministic runner execution. Codex CLI was available, but alpha testers should run one small real Codex CLI phase from the installed VSIX without a stub.
