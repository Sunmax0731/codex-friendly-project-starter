## Required alpha validation: real Codex CLI phase

Installed VSIX smoke for `v0.1.0-rc.2` used a runner stub/mock for deterministic phase execution. Codex CLI was available, but closed-alpha validation must include one small real Codex CLI phase from the installed VSIX without a mock or stub.

Suggested harmless phase:

```text
Ask Codex to inspect docs and write only docs/handoff/alpha-real-codex-cli.md.
Ensure logs go under .codexflow/logs/**.
Ensure no source files are modified unless explicitly intended.
```

Expected result:

```text
Real Codex CLI phase starts, completes or fails with clear error, and artifacts remain in safe paths.
```

Record the result in the feedback template below as `Real Codex CLI phase`.

## Safe ZIP validation expectations

ZIP import is for Codex Flow input files only. It is not a source-code patch package mechanism.

Allowed package contents:

```text
docs/**
prompts/**
.codexflow/flow.json
```

Forbidden package contents:

```text
src/**
package.json
package-lock.json
tests/**
dist/**
node_modules/**
.git/**
.env
.env.*
*.vsix
.codexflow/state.json
.codexflow/logs/**
.codexflow/run-prompts/**
.codexflow/backups/**
tmp/**
backup/**
*.bak
*.tmp
*.log
```

Runtime output restrictions:

```text
docs/handoff/**
.codexflow/logs/**
```

Import does not automatically start Run All. Run Next, Run All, and Repair require explicit user action. Unsafe runtime output paths are validation errors, not warnings.
